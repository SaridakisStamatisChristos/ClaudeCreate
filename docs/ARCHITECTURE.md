# Architecture and verification

**CLI:** `bin/reel.mjs` parses commands and delegates strict script validation to `src/spec.mjs` and HyperFrames composition creation to `src/composition.mjs`.

**Speech:** `src/audio/hyperframes.mjs` invokes the already-installed HyperFrames local Kokoro-82M TTS, followed by its local whisper.cpp `transcribe` command for word-level timestamps. This replaces the redundant Python Kokoro/faster-whisper dependencies. WAV duration is independently measured with FFprobe; every scripted word must match the ASR timestamps in sequence, or the render fails rather than fabricating captions. Validated metadata and WAV are cached by text, voice and adapter version, and cached WAV contents are checked against a SHA-256 digest. See [Native HyperFrames speech integration](HYPERFRAMES_VOICE.md).

**Video:** Each template is a timed HTML clip with a registered paused GSAP timeline. A single caption component builds word spans, reveals them at exact timestamps and colors the matching highlight. 3D scenes use a local `three.module.js` copy with deterministic time-based animation and a CSS fallback if WebGL fails. No CDN resources are referenced. The generated HyperFrames project resides in `.reel-work` and is not a server app.

**Audio:** FFmpeg places each voice/sfx file using sample-aligned per-scene delays, optionally includes a provided music track, and runs measured two-pass `loudnorm` with −14 LUFS / −1.5 dBTP target. The normalized track is muxed into vertical MP4; a blurred, darkened landscape reframe is created by FFmpeg. Thumbnails and caption are extracted/written afterwards.

**Style:** `tools/style_scan.py` analyzes references offline at 4 fps, measures scene-cut counts, and emits up to two 5×5 contact sheets per reel. Font and position estimates need human review. No unsupported claims of automatic typography detection.

**Testing:** `node tools/hyperframes_smoke.mjs` runs a real 1-second local HyperFrames rendering smoke test (requires npm packages but not Kokoro). `python3 tools/smoke_test.py` runs the actual FFmpeg export pipeline against a mock native HyperFrames TTS/transcription/render executable and deterministic synthetic WAVs. This is not a genuine HyperFrames or Kokoro test. `node --test` exercises the JSON schema, six template emission, escaping, strict word alignment and the native HyperFrames CLI adapter using mocks, without TTS models or network. Use `npm run test:real` on a machine able to download/load the HyperFrames Kokoro and Whisper models; this exercises genuine speech, transcription and FFmpeg-rendered MP4s. See [verification evidence](VERIFICATION.md). Never interpret static green tests as proof a video was rendered. `--draft` bounds render to <=10s.

**Current known limits:** Default Kokoro voice examples are English; other languages require compatible phonemization and may not align. Full rendering is CPU/GPU intensive. Actual cuts, style and WPM cannot be derived from references until videos are supplied. User-provided music licenses are the user's responsibility. HyperFrames downloads Kokoro and Whisper model assets once unless already cached; no paid inference API is used. Python3 is used only for standard-library sound-effect synthesis and test tooling; no pip or venv required.
